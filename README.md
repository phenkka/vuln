# VulnShop — учебное приложение по OWASP Top 10:2025

**VulnShop** — это маленькое намеренно уязвимое веб-приложение на **Flask (Python)**
с базой данных **SQLite** и шаблонами **Jinja2**. Оно создано как тренажёр: на нём
отрабатывают поиск, эксплуатацию и исправление уязвимостей из списка
**OWASP Top 10:2025** (редакция, опубликованная в ноябре 2025 — первое обновление с 2021 года).

> **Приложение уязвимо специально.** Не разворачивайте его в интернете, в общей
> сети или в любом окружении, где есть ценные данные. Запускайте только на `localhost`
> или в изолированной VM/контейнере без доступа к чувствительным сервисам. Никогда не
> переносите код из этого репозитория в реальный проект.

## Зачем этот проект

Цель — учебная и демонстрационная. На живом, но безопасно изолированном примере можно:

- **увидеть, как выглядят уязвимости в коде** — каждая категория OWASP представлена
  реальным уязвимым маршрутом в `app.py`;
- **потренировать инструменты DevSecOps** — SAST, SCA (сканеры зависимостей),
  DAST и ручной анализ находят здесь настоящие срабатывания, а не «пустышки»;
- **научиться исправлять** — к каждой категории ниже есть раздел с правильным
  решением (parameterized queries, bcrypt, security headers и т.д.);
- **проверить CI/CD-пайплайн** — репозиторий содержит `.gitlab-ci.yml` со стадиями
  безопасности, которые должны ловить эти уязвимости автоматически.

Каждый маршрут в `app.py` помечен комментарием вида `# [A05:2025-Injection]`, чтобы
можно было быстро найти уязвимый код по категории.

## Какие уязвимости здесь есть (OWASP Top 10:2025)

Приложение намеренно содержит по уязвимости (или нескольким) на каждую категорию:

| Код | Категория | Что реализовано в приложении |
|---|---|---|
| **A01** | Broken Access Control | IDOR на `/profile`, отсутствие проверки доступа на `/admin`, SSRF на `/fetch-avatar` |
| **A02** | Security Misconfiguration | `DEBUG=True`, захардкоженный `secret_key`, отсутствие security-заголовков |
| **A03** | Software Supply Chain Failures | устаревшие зависимости с известными CVE в `requirements.txt` |
| **A04** | Cryptographic Failures | пароли хешируются несолёным MD5 |
| **A05** | Injection | SQL-инъекция на `/login`, reflected/stored XSS на `/search` и `/notes`, command injection на `/ping` |
| **A06** | Insecure Design | нет rate-limit/блокировки на `/login`, предсказуемые нестареющие токены сброса пароля |
| **A07** | Authentication Failures | сессии не ротируются и не истекают, нет повторной аутентификации, отсутствуют флаги cookie |
| **A08** | Software or Data Integrity Failures | небезопасная десериализация (pickle) в `/set-theme`, неограниченная загрузка файлов `/upload` |
| **A09** | Security Logging & Alerting Failures | события входа не логируются, таблица `logins` не заполняется |
| **A10** | Mishandling of Exceptional Conditions | необработанные исключения на `/calc` плюс открытый интерактивный отладчик (из-за A02) |

Источник категорий: https://owasp.org/Top10/2025/

## Запуск

```bash
git clone <repo-url>
cd vulnshop-owasp-top10-2025
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

При первом запуске создаётся свежая база `vulnshop.db`, приложение слушает
`http://127.0.0.1:5000`.

Либо через Docker:

```bash
docker-compose up --build
```

Тестовые учётные записи:

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin123 | admin |
| alice | alicepw | user |
| bob | bobpw | user |

## Исправление уязвимостей

После того как разберёшь каждую категорию, можно попробовать пропатчить `app.py`:
параметризовать SQL-запросы, убрать `|safe` из шаблонов, заменить MD5 на bcrypt,
подписать cookie темы, добавить rate-limit, выставить `DEBUG=False` и security-заголовки.
Diff «до/после» — хороший артефакт для портфолио.
