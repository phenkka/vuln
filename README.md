# DevSecOps-конвейер для VulnShop на одном ноутбуке

Этот репозиторий — реализация CI/CD с проверками безопасности: локальный GitLab,
конвейер с гейтами, staging-VM с DAST, SCA через SBOM и Dependency-Track, телеметрия
в OpenSearch. Всё поднимается скриптами с нуля на одной машине (Docker + одна VM),
без платных и облачных сервисов, и после первой загрузки образов работает офлайн.

Проверяемое приложение — **VulnShop**, намеренно уязвимый Flask-магазин (OWASP Top 10:2025).
Здесь важно не оно, а то, как его собирают, проверяют и разворачивают; описание самого
приложения — в [docs/VULNSHOP.md](docs/VULNSHOP.md).

- Инструменты и их версии — [TOOLS.md](TOOLS.md)
- Скрипты стенда, порядок запуска и сноса — [infra/README.md](infra/README.md)

## Что сделано

- **Стенд одной командой на компонент.** Три идемпотентных скрипта поднимают GitLab с
  раннером, staging-VM и сервисы (OpenSearch, Dependency-Track). Повторный запуск ничего
  не ломает, `--reset` сносит и поднимает заново.
- **Гейты безопасности в каждом прогоне:** секреты во всей истории git, SAST, SCA по SBOM,
  проверка Dockerfile, DAST по задеплоенному приложению. Отчёты сохраняются артефактами
  даже при красном гейте.
- **SBOM в пайплайне** — CycloneDX 1.6 по каждому образу и по `package-lock.json` фронтенда.
- **SCA в Dependency-Track:** одна уязвимость считается один раз, между прогонами видно
  новое и исправленное, false positive помечается с обоснованием.
- **Деплой на staging-VM по SSH**, образы приходят на VM из приватного registry.
- **Телеметрия:** находки всех сканеров в общей схеме, события джоб и логи приложения с VM
  попадают в OpenSearch.

## Архитектура

```
+------------------ Ноутбук: Docker Desktop, сеть 172.30.0.0/24 ------------------+
|                                                                                 |
|  +------------------+  берёт джобы  +---------------+  запускает  +----------+  |
|  | GitLab CE        |<--------------| GitLab Runner |------------>| DinD:    |  |
|  | + Registry       |               +---------------+             | CI-джобы |  |
|  | 172.30.0.10      |<---------- push / pull образов -------------|          |  |
|  +------------------+                                             |          |  |
|                                                                   |          |  |
|  +------------------+             SBOM -> находки                 |          |  |
|  | Dependency-Track |<--------------------------------------------|          |  |
|  | 172.30.0.30      |                                             |          |  |
|  +------------------+                                             |          |  |
|                                                                   |          |  |
|  +------------------+         находки, события джоб               |          |  |
|  | OpenSearch       |<--------------------------------------------|          |  |
|  | 172.30.0.20      |<--+                                         +----------+  |
|  +------------------+   |                                              |        |
|  | Dashboards       |   |                                              |        |
|  +------------------+   |                                              |        |
|                         |                                              |        |
+-------------------------|----------------------------------------------|--------+
                          | логи                          SSH: деплой,   |
                          |                               ZAP: атаки     |
+-------------------------|------- VM staging (Multipass) ---------------|--------+
|                         |                                              |        |
|  +------------------+   |                         +-------------------+|        |
|  | Fluent Bit       |---+                         | backend   :5000   |<        |
|  |                  |<----- логи контейнеров -----| frontend  :80     |         |
|  +------------------+                             +-------------------+         |
|                                                                                 |
+---------------------------------------------------------------------------------+
```

- Все порты сервисов опубликованы только на `127.0.0.1` — снаружи ноутбука ничего не видно.
- Джобы выполняются в отдельном Docker-демоне (DinD), а не в Docker хоста, и сами
  запускаются без `privileged` (privileged только контейнер DinD — без этого Docker внутри
  не работает).
- Registry слушает только localhost, поэтому джоба деплоя открывает обратный SSH-туннель,
  и VM скачивает образы через него — своего доступа к GitLab у VM нет.
- Секреты в CI — protected-переменные (ключ Dependency-Track ещё и masked); SSH-ключ VM —
  отдельный пользователь `deploy` с запретом всего, кроме нужного проброса портов.

## Пайплайн

```
+----------------- build ------------------+  +---------------- scans ------------------+
|                                          |  |                                         |
|  build-images --+--> syft-sbom ------------------> dt-sca                             |
|  (Kaniko)       |    (SBOM 1.6)          |  |      (SCA, Dependency-Track)            |
|                 |                        |  |                                         |
|                 +--> test-stage -----------------> zap-scan                           |
|                      (деплой на VM)      |  |      (DAST)                             |
|                                          |  |                                         |
+------------------------------------------+  |  стартуют сразу, без сборки:            |
                                              |    gitleaks          (секреты)          |
                                              |    semgrep           (SAST)             |
                                              |    trivy-container   (Dockerfile)       |
                                              +--------------------+--------------------+
                                                                   |
                                                                   v  отчёты всех джоб
                                              +----------------- report ----------------+
                                              |  telemetry  -->  OpenSearch             |
                                              +-----------------------------------------+
```

Гейты `gitleaks`, `semgrep` и `trivy-container` стартуют сразу (`needs: []`), не дожидаясь
сборки. Деплой зависит только от сборки и не блокируется красными гейтами. `telemetry`
выполняется всегда (`when: always`) и собирает отчёты всех джоб.

| Стадия | Джоба | Инструмент | Что делает | Гейт падает, если | Артефакты |
|---|---|---|---|---|---|
| build | `build-images` | Kaniko | собирает backend и frontend, пушит в registry | — | digest'ы образов |
| build | `syft-sbom` | Syft | SBOM образов (backend, frontend) и `package-lock.json` фронтенда | — | `sbom-*.cdx.json` (CycloneDX 1.6) |
| build | `test-stage` | ssh, Docker | деплой образов на VM по digest, проверка, что сайт отвечает | приложение не поднялось | — |
| scans | `gitleaks` | Gitleaks | секреты во всей истории git | любая находка | `gitleaks-report.json` |
| scans | `semgrep` | Semgrep | SAST по Python и JavaScript | `ERROR` / `WARNING` | `semgrep-report.json` |
| scans | `dt-sca` | Dependency-Track | SCA: отправляет 3 SBOM, ждёт анализа, забирает находки | `CRITICAL` / `HIGH` | `dt-findings-*.json` |
| scans | `trivy-container` | Trivy | ошибки конфигурации обоих Dockerfile | `CRITICAL` / `HIGH` | `trivy-config-*.json` |
| scans | `zap-scan` | OWASP ZAP | baseline по frontend, full scan по backend | риск `High` | `zap-*.json`, `zap-*.html` |
| report | `telemetry` | Python | находки и события джоб → OpenSearch | — (не гейт) | — |

Приложение уязвимо специально, поэтому гейты **красные**: это результат проверки, а не сбой.

## Как развернуть

Нужны Docker Desktop (Compose v2), Multipass, `git`, `curl`, `openssl` и интернет при
первом запуске.

```bash
cd infra
./setup-gitlab.sh        # GitLab, раннер, DinD; импорт репозитория
./setup-staging-env.sh   # staging-VM, Fluent Bit, CI-переменные для деплоя
./setup-opensearch.sh    # OpenSearch, Dashboards, Dependency-Track (первый раз ~7 мин)
```

Первый пайплайн стартует сам при импорте — ещё до VM и сервисов, поэтому он частично
упадёт. После третьего скрипта: GitLab → Build → Pipelines → **Run pipeline**.

Подробности по каждому скрипту, требования, снос стенда и типичные ошибки —
в [infra/README.md](infra/README.md).

## Где смотреть результаты

| Что | Где |
|---|---|
| Пайплайн, отчёты и SBOM | `https://gitlab.test` → проект → Build → Pipelines → артефакты джоб |
| Уязвимые компоненты, история, пометки false positive | Dependency-Track `http://127.0.0.1:8081` (пароль печатает `setup-opensearch.sh`) — проекты `<проект>-backend`, `-frontend`, `-frontend-deps` |
| Все находки, события джоб, логи приложения | OpenSearch Dashboards `http://127.0.0.1:5601` → Discover → `findings*`, `pipeline-events*`, `app-logs*` |

## Ключевые решения

- **SBOM из двух источников для фронтенда.** В образ фронтенда библиотеки попадают просто
  файлами `.min.js` без метаданных, и сканер образа их не видит (известное ограничение и
  Syft, и Trivy). Поэтому SBOM делается и по образу (ОС, nginx), и по `package-lock.json`.
- **SCA — Dependency-Track, а не сканер в каждой джобе.** Одна точка правды по
  компонентам: дедупликация между прогонами, история, аудит находок. Ключ CI — отдельная
  команда в DT с минимальными правами.
- **Trivy только для Dockerfile.** Уязвимости образов уже считает Dependency-Track;
  `trivy image` дал бы те же CVE второй раз.
- **DAST: baseline недостаточно.** Пассивный baseline не находит SQL-инъекцию и command
  injection; их находит только активный full scan по backend.
- **Офлайн после первой загрузки:** раннер берёт образы из кэша (`if-not-present`),
  Dependency-Track хранит базу OSV в своём томе, образ Fluent Bit доставляется на VM
  файлом с хоста.

## Ограничения

- OpenSearch и Dependency-Track работают по HTTP, у OpenSearch выключен security plugin:
  порты доступны только с localhost и моста Multipass. Для продакшена нужны TLS и пользователи.
- Правила Semgrep и проверки Trivy скачиваются из интернета при каждом запуске.
- ZAP сканирует без авторизации.
- В логах приложения все запросы приходят с адреса хоста (`192.168.252.1`) — это NAT
  Multipass, реальный IP клиента не виден.
